# 管理员账号管理（超级用户）

本文档说明如何 **查看 / 重置 / 创建** My-Blog 的超级管理员（superuser）账号。

> ⚠️ 安全须知：本项目**不**在代码仓库或文档中明文存储任何管理员密码。
> 数据库账号 `myblog_user`（密码见 `scripts/server-init.sh` 中的 `DB_PASSWORD`）**不是**后台登录账号，
> 仅用于 Django 连接 PostgreSQL，请勿混淆。

---

## 0. 账号体系说明

| 账号类型 | 用途 | 创建方式 |
|----------|------|----------|
| PostgreSQL 数据库账号 `myblog_user` | Django 连接数据库 | `server-init.sh` 自动创建 |
| Django 超级管理员（superuser） | 登录后台管理博客 | `createsuperuser` / `changepassword` 手动维护 |

后台登录使用的是 **Django 超级管理员账号**，由你在服务器上自行创建，仓库内无记录。

---

## 1. 线上环境（Docker 容器部署）

当前线上架构：Docker 容器运行 Django（gunicorn），宿主机 PostgreSQL，
项目根目录 `/home/deploy/my-blog`，容器名以 `my-blog` 相关命名。

### 1.1 列出所有超级管理员

```bash
cd /home/deploy/my-blog
docker compose exec web python manage.py shell -c "
from django.contrib.auth import get_user_model
U = get_user_model()
for u in U.objects.filter(is_superuser=True):
    print(u.username, '| email=', u.email, '| staff=', u.is_staff)
"
```

### 1.2 重置某用户的密码（记得用户名）

```bash
cd /home/deploy/my-blog
docker compose exec -it web python manage.py changepassword 你的用户名
# 按提示输入两次新密码
```

### 1.3 创建新的超级管理员

```bash
cd /home/deploy/my-blog
docker compose exec -it web python manage.py createsuperuser
# 按提示填写 用户名 / 邮箱 / 密码
```

> 若 `docker compose` 报 "no configuration file"，请确认在 `docker-compose.yml` 所在目录执行，
> 或改用 `docker compose -f docker-compose.yml exec web ...`。

## 2. 本地 / 非 Docker 环境（venv + manage.py）

适用于本地开发或按 `DEPLOY.md` 非 Docker 方式部署的服务器（项目根 `/opt/my-blog`）。

先激活虚拟环境：

```bash
cd /opt/my-blog        # 或你的项目根目录
source venv/bin/activate
```

```bash

from django.contrib.auth import get_user_model

python manage.py changepassword 你的用户名
```

### 2.3 创建超级管理员

```bash
python manage.py createsuperuser
```

## 3. 认证与登录入口

- 本项目为**双会话机制**：前台用户会话与后台管理员会话隔离。
- 后台登录入口通常位于前台导航的「后台」链接，或访问 `/admin/` 路径（取决于 `users` 应用路由）。
- 管理员登录走 Django Session 认证，非 API Token。

---

## 4. 常见问题

**`changepassword` 提示用户不存在**
先用「列出超级管理员」命令确认正确的 `username`，注意大小写。

**Docker 内执行命令无反应 / 卡住**
`changepassword` / `createsuperuser` 是交互式命令，需加 `-it` 参数分配伪终端；
非交互场景（脚本）优先用 `shell -c` 内联命令。

**忘记所有管理员账号且无法登录**
用「创建新的超级管理员」（1.3 / 2.3）新建一个账号登录后台，再在后台管理界面处理旧账号。

**重置密码后仍登录失败**
- 确认访问的是后台入口，而非前台用户登录；
- 清除浏览器 Cookie 后重试（避免旧 Session 干扰）；
- 检查 `ALLOWED_HOSTS` 是否包含当前域名。

**`create_superuser` 报错 `UNIQUE constraint failed` / 提示已存在**
说明该用户名（如 `admin`）此前已创建过，无需重复创建。
先用「列出超级管理员」命令确认账号是否存在；若已存在但忘记密码，改用 `changepassword 用户名` 重置，而非再次创建。
（实战记录：线上 `admin` 账号已存在且为 superuser，直接登录或重置密码即可。）

---

## 5. 安全建议

- 超级管理员密码应使用强密码（≥12 位，含大小写+数字+符号），勿与数据库密码相同。
- 不要在命令行历史、脚本、聊天工具中明文留存管理员密码。
- 多人协作时，各自创建独立 superuser，避免使用共享账号。
- 怀疑账号泄露时，立即用 `changepassword` 重置并审查后台活动。
